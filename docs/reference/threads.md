# Threads

Worker threads `main.py` starts, in start order, and what `/healthz` does about them.

| name | interval | reads | writes | on failure | critical |
|---|---|---|---|---|---|
| `TelegramAdapter` | Polls the `telegram_bot_token` setting every 30 s (`TOKEN_POLL_SECONDS`) while no bot is running; restarts the bot 5 s (`RESTART_BACKOFF_SECONDS`) after the token changes or the bot loop exits. | `telegram_bot_token`, `public_base_url`; `user_pages`, `page_subscribers`, `subscribers`, `pending_registrations` on each inbound command. | `telegram_bot_username` (once, on connect); `user_pages`, `page_subscribers`, `subscribers`, `pending_registrations` from inbound commands. | Logs the exception and restarts the bot after the backoff; the supervisor loop itself never exits. | No |
| `PollingThread` | `poll_interval_minutes` (default 15 min); falls back to 15 min if the setting can't be read. | Active `sites`; `historical_start_year`, `low_percentile`, `high_percentile`, `very_low_percentile`, `very_high_percentile`, `rate_change_*` settings; USGS `nwis.get_iv` / `get_dv`. | `site_conditions`; `sites.last_success_at` / `last_error` / `last_error_at`; enqueues `transition` and `trend` items. | Logs the exception and retries on the next interval. | Yes |
| `NoaaPollingThread` | `poll_interval_minutes` (default 15 min); same fallback. | Active `noaa_gauges`; NOAA NWPS current-stage API. | `noaa_observations`; `noaa_gauges.current_stage` / `severity` / `last_polled_at`; enqueues `noaa_transition` items. | Logs the exception and retries on the next interval. | Yes |
| `ForecastPollingThread` | `forecast_poll_hours` (default 6 h); same fallback. | Active `noaa_gauges`; NOAA NWPS forecast API; `noaa_observations` and `gauge_forecasts` (for grading). | `gauge_forecasts`; `noaa_gauges.has_forecast` / `forecast_checked_at` / `quality_grade` / `quality_detail` / `quality_checked_at`. | Logs the exception and retries on the next interval. | Yes |
| `SchedulerThread` | Reminders every 300 s (`CHECK_INTERVAL_SECONDS`); retirement sweep every 3600 s (`SWEEP_INTERVAL_SECONDS`). | `sites` + latest `site_conditions`; `notifications` (last reminder sent); `reminder_low_high_hours`, `reminder_severe_hours`. | Enqueues `reminder` items; the sweep deactivates unreferenced `sites` / `noaa_gauges` and retires stale `user_pages`. | Reminder pass: logs and retries next 300 s pass. Sweep: logs and leaves its internal timer alone, so the next reminder pass (≤ 300 s later) retries it, instead of waiting a full hour. | Yes |
| `NotificationDispatcher` | Blocking `queue.get(timeout=1)` — reacts within 1 s of an item being queued, otherwise loops idle. | The notification queue; `page_subscribers` / `subscribers` for recipients (via `alert_allowed`). | `notifications` (one row per delivery attempt, success or failure). | Logs the exception for that item and continues the loop; one bad item or DB blip cannot stop delivery. | Yes |
| `WebThread` | Not polling — serves continuously via waitress, 8 worker threads, port 5743. | Whatever the handled route reads. | Whatever the handled route writes. | Not applicable; an unhandled exception in a request becomes a 500 for that request only. | Yes |

The supervisor (`main.py: supervise`) checks every 60 s (`SUPERVISOR_INTERVAL_SECONDS`) and, if a thread named in `CRITICAL_THREADS` has died, logs it and exits the process non-zero so Docker's `restart: unless-stopped` policy brings the container back; a dead non-critical thread (`TelegramAdapter`) is only logged. `GET /healthz` reports each thread in the registry's `is_alive()` state independently and returns 503 if any of them — critical or not — is dead, so a container that still serves pages but has a stopped worker is flagged unhealthy even before the supervisor would act.

Compose's `restart: unless-stopped` policy does **not** itself act on an `unhealthy` healthcheck status — it only restarts the container when the process inside it exits, which is exactly what the supervisor does on a critical thread's death. A dead non-critical thread (`TelegramAdapter`) never makes the process exit, so `/healthz` stays at 503 indefinitely with no automatic recovery; an operator has to notice and run `docker compose restart app` themselves.
